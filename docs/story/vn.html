Dialogue scripts (.vn)

Write a scene as plain text. events/town/sign/index.vn becomes the event 'town/sign', just like an index.ts would. So does the single file events/town/sign.vn.

An example

# The town sign. Lines starting with # are comments.
title The town sign
> An old wooden sign. Someone carved a message into it.
> {i}"Welcome to town. Be kind to the slimes."{/i}

if flag('read_sign'):
  > You have read it before. It hasn't changed.
else:
  set read_sign = true
  > Behind the sign, half buried, something glints.
  choice:
    * Dig it up
      give apple
      money +5
      > An apple and a few coins. Lucky!
    * Leave it
      > You leave it where it is.

A file in src/content/routes/ is a route script instead (the story's order in visual novel mode): see Routes & flowchart.

Every file needs one title line (not indented, usually at the top): the event's name on saves made during it, like a map's title.

Blocks are made by indenting (spaces): the options of a choice:, and the body of if / elif / else. Blank lines don't matter.

One file per scene

A scene does not need a folder of its own. Any <name>.vn file in src/content/events/ or one of its group folders is an event, named by its path:

src/content/events/
  common/day1_morning.vn        # the event 'common/day1_morning'
  common/day1_lunch.vn          # 'common/day1_lunch'
  common/day1_evening/index.vn  # 'common/day1_evening' (a folder, e.g. to keep its pictures with it)
  common/_notes.vn              # ignored (starts with _)
  • The generated file sits next to it (day1_morning.gen.ts).
  • Voice files, saves and read lines go by the event id, so a scene can move between the two forms freely. When you turn a folder into a file, delete the folder (a folder and a file with the same name: the folder wins, with a warning).
  • Only .vn scenes can be single files; a scene written in TypeScript keeps its folder with index.ts.

How it works

  • The file is compiled to index.gen.ts next to it: on save while the dev server runs, and by pnpm gen / pnpm typecheck. Don't edit the generated file.
  • The generated code is ordinary TypeScript, so wrong ids are type errors in pnpm typecheck. Every generated line has a comment with its .vn line number.
  • Mistakes are also printed by the dev server, e.g. [vn] events/town/sign/index.vn:12:6: unknown item "aple" (did you mean "apple"?).
  • A folder with both index.ts and index.vn uses the index.ts.
  • Translations: pnpm lang reads .vn files too (lines, options, narration).

Put a value into a line with [ ], like Ren'Py: anna: You have [money()] coins. Inside the brackets is TypeScript (a variable from a $ line, a helper, game.…). Translators see {money}. Write [[ for a plain [.

Text supports the same markup: {b}, {i}, {color=…}, {size=…}, {shake}, {wave}, {w=0.5}.

At the same time

Commands like fade wait until they finish. Put meanwhile in front to start one and go on at once:

meanwhile fade #ffffff51 2000
meanwhile $ await animate('god', { opacity: 1 }, { duration: 1000 })
hero: Ehh... What?

together: starts every line below it at once and goes on when all of them are done:

together:
  hero: Ehh... What?
  fade #ffffff51 2000
  $ startShake(6)
fade #ffffff 2000
  • There is one chat box, so only one line in a together: block can be dialogue, narration, a choice or an event.
  • Dialogue can't be meanwhile (it always waits for the player); wait, event and end can't either. end can't be inside together:.
  • A block inside together: (an if, a choice) counts as one line: its own lines run in order.

Choices and conditions

Condition helpers: flag('name'), has('item'), love('anna'), money(), inParty('hero'), seen('event/id') (see Run once) and variant('adult') (this build's content variant).

choice:
  * Yes, please
    anna: Great!
  * Only friends see this if love('anna') >= 10 and not flag('met_anna')
    > A secret option.
  * No

if flag('met_anna'):
  anna: Again?
elif has('apple', 2) or money() > 50:
  anna: Rich!
else:
  anna: Hi.
  • An option with if … at the end is hidden unless the condition is true.
  • Conditions are TypeScript with helpers and the words and, or, not.

Editor extension

Kroniki VN Scripts, for VSCodium / VS Code: colouring, suggestions and red underlines while you type.

  1. Build it: pnpm vn:extension → build/vn-extension/kroniki-vn-scripts-<version>.vsix.
  2. In the editor's Extensions view: the … menu → Install from VSIX… → pick that file.
  • Suggestions by context: characters and commands at the start of a line, poses after anna: or pose, stage positions after at, items after give, enemies and troops after battle, sounds after music, flags after set or inside flag(', markup tags after {.
  • Checks as you type: unknown ids with "did you mean", lines it doesn't understand, bad indentation, a voice number one speaker already used in the file.
  • Voice numbers: after anna( the first suggestion is Anna's next free number in this file (0008); after voice the recorded clips of other events.
  • New content works at once. The ids are read from the open project and re-read when anything in src/content changes. You only rebuild/reinstall when the extension itself changes (bump the version in tools/vscode-vn/package.json).
  • The title bar button VN: Show generated TypeScript opens the index.gen.ts beside it.

The rules live in vite/vn/: compile.ts (to TypeScript), check.ts (ids), complete.ts (suggestions), ids.ts (reads the project). The extension and the dev server share them.

Adding a command

  1. Add a case in command() in vite/vn/compile.ts (it returns one line of TypeScript).
  2. If its argument is an id, add it to COMMAND_ARGS in check.ts; add a suggestion to COMMANDS in complete.ts; add the word to the grammar in tools/vscode-vn/syntaxes/vn.tmLanguage.json.
  3. Add a test in vite/vn/*.test.ts, update this page, rebuild the extension.
